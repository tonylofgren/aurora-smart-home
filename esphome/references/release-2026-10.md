## Upgrade decisions

| Area | What to do |
|---|---|
| ESP8266 | Native `arduino` toolchain is now default. Use `toolchain: platformio` only for unsupported boards/custom frameworks; removal is scheduled for 2027.4.0. First native build is clean. |
| Host | Native Ninja replaces PlatformIO. Host firmware uses POSIX interfaces; Windows host builds are unsupported. This does not prevent building ESP32/ESP8266 firmware on Windows. |
| Speaker | Remove `codec_support_enabled`. Pipeline `format: NONE` selects all codecs. Volume changes no longer imply mute changes. |
| Sendspin | Upgrade Music Assistant to 2.10.7 or 2.11.0b4+ first. ESP-IDF is required; links are encrypted. Include FLAC or PCM if explicitly listing codecs; replace BMP images with JPEG/PNG. Switches need `type`. |
| IR climate | If heat or cool is disabled, combined HEAT_COOL is no longer implicitly advertised. Set `supports_heat_cool: true` only when wanted and supported. |
| Hörmann | Commands while moving stop the door; lamp commands represent an absolute state. Recheck automations that burst commands. |

Details: [ESP8266](https://esphome.io/components/esp8266/),
[speaker](https://esphome.io/components/media_player/speaker/),
[October breaking changes](https://esphome.io/blog/2026/10/21/esphome-2026-10/#breaking-changes).
Do not treat every deprecation as a removed key.

## Lights: migrate deliberately

`restore_state` replaces `restore_mode` for lights, but the old key remains accepted
and has no scheduled removal. The options are mutually exclusive. `restore_state: all`
restores saved fields; `none` disables restoration. Per-field overrides are also supported.
First boot has no saved state, so `initial_state` supplies the fallback.

```yaml
# Fragment: restore previous values, but use OFF on first boot.
light:
  - platform: monochromatic
    output: confirmed_pwm_output
    name: Reading light
    initial_state:
      state: false
    restore_state: all
```

When neither restore option is set, `initial_state.state: ON` now actually boots ON.
Test boot behavior instead of mechanically replacing enum strings with a boolean.
This change is specific to **lights**; do not rewrite switch `restore_mode` keys.
New options also include resuming the last effect and publishing transition states;
actions can use named colors. See [light configuration](https://esphome.io/components/light/).

## OTA: encryption and compression solve different problems

September introduced encrypted transport; October adds an explicit single-install
migration path. With pre-September firmware, either keep the two-step procedure or set
`encryption.allow_plaintext_upload: true` for the first install while retaining its old
password. The installed firmware requires encryption. Remove the fallback and password
afterward. Preserve the real API key, including a key provisioned by HA.

```yaml
# Transitional fragment only; existing API encryption key must already be in config.
ota:
  - platform: esphome
    password: !secret ota_password
    encryption:
      allow_plaintext_upload: true
```

For an MQTT-only node, put its own key inside `encryption:`. The two-step MQTT migration
instead temporarily needs an encrypted `api:` with `reboot_timeout: 0s`.
See [security-hardening.md](security-hardening.md) for the complete migration.

Compression needs no YAML setting. ESP32, RP2040, LibreTiny and host use it when both
running firmware and uploader support 2026.10; old peers fall back to uncompressed
transport. ESP8266 already compressed OTA. Do not promise compression on the first upgrade.
Source: [OTA documentation](https://esphome.io/components/ota/esphome/).

## Serial, USB and networking

Choose by direction and protocol:

| Need | Use |
|---|---|
| HA accesses a device UART through authenticated ESPHome API | `serial_proxy` |
| A computer USB port becomes a device UART | `bridge: platform: cdc_acm_uart` |
| Share that physical UART between USB and a local decoder | `uart_mux` |
| A local ESPHome decoder reads bytes over TCP | `tcp_uart` |
| Forward physical UART bytes to/from TCP | `uart_tcp` |

`serial_proxy` requires a name and electrical `port_type`, not a TCP `port:` option.
Only its active subscriber may write/configure/change mode. `RAW` passes bytes unchanged;
`PROTOCOL` is an extension point, not a bundled protocol decoder. USB identity and
`USB_SERIAL` ports improve discovery. Source: [Serial Proxy](https://esphome.io/components/serial_proxy/).

Other additions: KSZ8851SNL SPI Ethernet; forced WiFi roaming checks; USB descriptor
matching and communication-interface claiming; TinyUSB mount triggers; outgoing native
API connections. Overlapping USB matches need manufacturer/product filters. Consult
[October changes](https://esphome.io/changelog/2026.10.0/) and the catalog before generating YAML.

## API and Home Assistant

`api.outgoing_connection` allows the device to initiate a connection; encryption is
required. It does not automatically make an unreachable network route available.
`api.wizard` provides onboarding pages, but the UI **requires HA 2026.11**; earlier HA
versions ignore it. Do not promise a visible wizard on HA 2026.10.
The new HA text/select/button platforms let a device use those HA entities directly.
Source: [Native API](https://esphome.io/components/api/) and
[onboarding version note](https://esphome.io/blog/2026/10/21/esphome-2026-10/#setup-wizard-for-home-assistant-onboarding).

## Displays, sensors, audio and other features

The [catalog](new-components-2026-9-10.md) maps new hardware to actual examples.
Additional improvements include LVGL animation updates, touch support, AMOLED brightness,
SSD1681 panels, e-paper update status/full refresh, motion gestures, Zigbee measurement
clusters and number/switch support, PID deadband actions, DFPlayer track repeat,
Sendspin identity options, and conditional includes in substitutions.

For e-paper, check luminance conversion, panel partial-refresh support and PSRAM
requirements. The reTerminal Sticky needs PSRAM; `full_update_every` values above one
are inappropriate for panels without partial refresh. See
[ePaper SPI](https://esphome.io/components/display/epaper_spi/).

Remote receiver buffer sizes are bytes on pulse-ring targets. Existing explicit values
on ESP8266, RP2040, LibreTiny, ESP32-C2/C61 need review (four times the former count keeps
the same pulse capacity); RMT defaults also changed. See
[Remote Receiver](https://esphome.io/components/remote_receiver/).

Build, API throughput and memory improvements generally need no YAML migration.
Do not reproduce benchmark numbers as guaranteed gains for a user's hardware.

## External components and lambdas

Check tagged source when maintaining C++: sensor `raw_state` becomes `get_raw_state()`;
removed Modbus helpers move to `modbus::helpers`; remote protocol registration and virtual
methods changed; NFC tag/record ownership changed; PN7150/PN7160 share `pn71xx`; audio
files are flash constants. `register_apply_action` and sub-entity helpers replace much
code-generation boilerplate. A configuration check does not compile these C++ paths.
See the [developer migration notes](https://esphome.io/blog/2026/10/21/esphome-2026-10/#undocumented-api-changes)
and the [2026.10.0 source](https://github.com/esphome/esphome/tree/2026.10.0/esphome/components).

## Validation before delivery

Read the exact component prerequisites, adapt a catalog package to confirmed hardware,
run `esphome config`, then compile the resulting project. For a real deployment also
verify startup state, networking, sensors and recovery on hardware. Package fixtures
exercise ESPHome's schema; they are not evidence of successful physical operation.
