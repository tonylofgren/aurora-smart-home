# ESPHome 2026.9 / 2026.10 component packages

> *Generated by [aurora@aurora-smart-home (esphome skill)](https://github.com/tonylofgren/aurora-smart-home)*

These are reusable package fragments for ESPHome **2026.10.0**, not firmware for an
unidentified device. Except `snapshot-host.yaml`, include **one** package in a full node
configuration. Select the actual board, buses, supply and pin mapping before flashing.
The default GPIOs are illustrative ESP32-S3 pins. Do not assume they match a commercial board.
Packages may define the same buses/IDs: merge them deliberately rather than combining all files.

## Installation

Copy the chosen file beside your device YAML and include it with `packages:`. For example,
after confirming the board and STCC4 module:

```yaml
esphome:
  name: room-air
  min_version: 2026.10.0
esp32:
  board: esp32-s3-devkitc-1
  framework:
    type: esp-idf
logger:
  baud_rate: 0
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
api:
  encryption:
    key: !secret api_encryption_key
ota:
  - platform: esphome
    encryption:
packages:
  sensor: !include stcc4.yaml
```

This base is for a **new, USB-flashed** device. Preserve existing keys and use the
[OTA migration guide](../../../references/security-hardening.md) for installed firmware.
Do not copy test fixture keys into a device. Add actual private values to your project's
secret store; the BLE packages also need `scale_mac`/`scale_bindkey` or `door_mac`/`door_bindkey`.

Run `esphome config device.yaml`, then `esphome compile device.yaml`. A successful schema
check does not test wiring, compile C++ lambdas or demonstrate sensor accuracy.
`snapshot-host.yaml` instead runs as its own host configuration on Linux/macOS.

## Wiring, calibration and recovery

Additional October packages: [motion gestures](motion-gesture.yaml),
[KSZ8851SNL Ethernet](ksz8851snl.yaml), and [Improv BLE](improv-ble.yaml).
These also use illustrative S3 wiring; Improv authorization is a physical active-low
button, not permanently open provisioning.

For I2C, connect SDA/SCL to the selected pins and use the module's documented supply and
pull-up voltage. UART crosses peripheral TX to MCU RX and vice versa when TX is used;
share ground only where the interface design calls for it. Isolated RS485 and Systa bus
interfaces require their own wiring plan. Never connect a heating/energy bus directly to GPIO.
USB bridging uses the S3's native USB pins; GPIO19/20 are not available for another function.
TAS amplifiers need their specified power supply and a suitable speaker; they are not
powered from a GPIO. The T4-S3 example is specific to its integrated display.

Before delivery for real hardware, replace these assumptions with a per-pin wiring table
and module-specific supply, mounting and calibration instructions. This library is not
a wiring certification for unknown boards.

Likely failures: wrong bus/pin assignment, wrong sensor/MCU protocol (including Tuya DPs),
and missing secrets or external entity IDs. Check logs and bus detection first. Keep a
known-good firmware and USB recovery access before an OTA migration. CSI detection needs
empty-room calibration; tank depth needs couplant and a known depth; D01 conversion needs
comparison with a reference. Verify measurements before using them in automations.

Schema validation uses isolated fixtures in `aurora/tests/test_esphome_release_templates.py`.
Hardware behavior and live HA entity availability must be tested on the target installation.
