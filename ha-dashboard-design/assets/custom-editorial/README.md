# Custom Editorial dashboard

> *Generated by [aurora@aurora-smart-home (home-assistant skill)](https://github.com/tonylofgren/aurora-smart-home)*

## What this does

A warm paper theme with large serif typography, asymmetric desktop composition and a
single-column phone layout. HA supplies the states and light controls; the visual design
is independent of standard tiles. Requires **button-card** and **layout-card**. No
card-mod, Mushroom, external fonts, images or access tokens are needed.

`dashboard.yaml` and `theme.yaml` are reusable templates, not a discovered home setup.
Replace the six `*_replace_me` IDs with three real sensors and three lights. Sensor taps
open details; light taps toggle and holds open details. Missing data reads "Unavailable".
This template has been structurally checked, not rendered against a live HA instance.

## Installation

1. Install button-card and layout-card through HACS. Verify their resources are registered
   as JavaScript modules once; reload the browser. Typical URLs are
   `/hacsfiles/button-card/button-card.js` and `/hacsfiles/lovelace-layout-card/layout-card.js`.
2. Copy `theme.yaml` to `/config/themes/aurora-editorial.yaml`. Merge the following into
   your existing configuration rather than adding a second `frontend:` key:

```yaml
frontend:
  themes: !include_dir_merge_named themes/
```

3. Reload themes with `frontend.reload_themes` (restart after first enabling the themes
   include if necessary). The view selects `Aurora Editorial` by name.
4. Replace entity IDs, labels and icons. Change palette tokens in the theme and card
   spacing in the shared `button_card_templates` block to create your own variation.

### Option A: Raw Configuration Editor (recommended for trying it)

Create a separate editable dashboard, open its Raw Configuration Editor and paste the
entire `dashboard.yaml`, including `button_card_templates`. Save and verify every tile.

### Option B: Named YAML dashboard

Copy the file to `/config/dashboards/editorial.yaml` and merge this named dashboard into
the existing `lovelace:` configuration. It does not change other dashboards to YAML mode.

```yaml
lovelace:
  dashboards:
    editorial-home:
      mode: yaml
      title: Our home
      icon: mdi:home-outline
      show_in_sidebar: true
      filename: dashboards/editorial.yaml
```

Keep resources registered through your existing resource management. If resources are
managed in YAML, add the two module URLs there instead of also registering them in the UI.
Check the configuration and reload/restart as required for the new dashboard registration.

## Troubleshooting

- **Custom element does not exist:** check both module resources, HACS installation and
  browser cache. The exact types are `custom:layout-card` and `custom:button-card`.
- **Plain colors or missing typography:** confirm the theme file is loaded and that its
  name matches the view. Do not paste theme YAML into the dashboard editor.
- **Unavailable readings or controls that do nothing:** replace every placeholder and
  check actual states in Developer Tools. Ensure the user can access those entities.

Verify at 360 px, tablet and desktop sizes; test keyboard focus, long labels, light
on/off states and actual actions. The HA header/sidebar remains available intentionally.

## Recovery

Keep an export of the previous dashboard. Restore it through the Raw Configuration
Editor, or restore the YAML file and remove this named dashboard registration. Switch
back to the default theme. Use another HA dashboard to reach settings if the custom
cards fail. Prefer a backup restore over hand-editing `.storage/lovelace*` files.
